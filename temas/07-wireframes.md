# Wireframes

## El esqueleto antes del estilo

**Tagline:** Un wireframe permite decidir estructura, espacio y jerarquía antes de diseñar visualmente.

**Descriptor:** El wireframe es una representación simple del sitio. Muestra secciones, contenedores, orden, navegación, jerarquía y comportamiento general sin depender todavía de color, imágenes o tipografía final.

## Objetivo

Diseñar la estructura del sitio antes de programar. El wireframe evita improvisar el HTML y ayuda a revisar si el contenido cabe, si el recorrido funciona y si la jerarquía es clara.

## Cómo se consigue

Se consigue dibujando los bloques principales del sitio.

Puede hacerse en:

- papel;
- servilleta;
- Figma;
- Illustrator;
- Photoshop;
- herramienta de wireframing;
- captura de un boceto rápido.

Lo importante es que la estructura exista antes del HTML.

## Subtemas

### Desktop

El wireframe desktop debe mostrar:

- hero;
- navegación;
- contenedor;
- secciones principales;
- relación entre texto e imagen;
- jerarquía de títulos;
- CTA.

### Mobile

El wireframe mobile debe mostrar cómo se reorganiza el contenido en una pantalla más estrecha.

No basta con reducir el desktop. Hay que pensar:

- orden;
- legibilidad;
- tamaño de texto;
- espacio entre bloques;
- navegación.

### Bloques

En esta etapa se diseña con bloques verticales. Cada sección debe poder existir una debajo de otra.

Ejemplo:

```text
[ HERO ]
[ CONTEXTO ]
[ CATEGORÍA 1 ]
[ CATEGORÍA 2 ]
[ EJEMPLOS ]
[ CIERRE ]
```

### Del wireframe al diseño visual

Después del wireframe se aplica:

- color;
- tipografía;
- imagen;
- contraste;
- ritmo;
- detalles visuales.

## Evidencia esperada

El proyecto debe incluir:

- wireframe desktop;
- wireframe mobile;
- hero resuelto;
- secciones principales;
- nota breve de cómo se adapta el contenido.

## Errores comunes

- Programar sin wireframe.
- Hacer un wireframe que no corresponde al contenido.
- Diseñar solo desktop.
- No pensar en contenedores.
- No definir espacio entre secciones.
- No mostrar jerarquía.

## Preguntas de revisión

- ¿Se entiende qué aparece primero?
- ¿Hay un contenedor claro?
- ¿Las secciones tienen orden?
- ¿El mobile conserva jerarquía?
- ¿El wireframe ayuda a construir el HTML?
