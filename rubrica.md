# Rúbrica

## Sitio web en bloques

**Tagline:** Evaluar el proceso completo: investigar, estructurar, diseñar y construir.

**Descriptor:** Esta rúbrica mide el desarrollo de un sitio web sencillo a partir de información estructurada. Cada criterio vale 10 puntos. El total es de 100 puntos.

## Niveles

| Nivel | Rango |
|---|---:|
| Excelente | 9-10 |
| Bueno | 7-8 |
| Regular | 5-6 |
| Deficiente | 0-4 |

## Criterios

| Criterio | Puntos |
|---|---:|
| 1. Proceso de investigación y `PROMPT.md` | 10 |
| 2. Información estructurada en `INFO.md` | 10 |
| 3. Síntesis y selección de contenido | 10 |
| 4. Intención comunicativa | 10 |
| 5. Mapa de sitio y organización de secciones | 10 |
| 6. Tono verbal y visual | 10 |
| 7. Moodboard y referencias visuales | 10 |
| 8. Sistema visual mínimo | 10 |
| 9. Wireframes y diseño en bloques | 10 |
| 10. Implementación HTML/CSS y revisión | 10 |

## 1. Proceso de investigación y `PROMPT.md`

| Nivel | Descripción |
|---|---|
| Excelente | Documenta cómo investigó, qué preguntó, qué ajustó, qué fuentes o criterios utilizó y cómo tomó decisiones. El proceso muestra exploración real. |
| Bueno | Documenta prompts y respuestas principales, aunque falta explicar algunas decisiones o ajustes. |
| Regular | Incluye prompts de forma superficial, sin explicar cómo ayudaron al proyecto. |
| Deficiente | No entrega `PROMPT.md` o solo copia respuestas sin proceso visible. |

## 2. Información estructurada en `INFO.md`

| Nivel | Descripción |
|---|---|
| Excelente | La información está organizada con títulos, subtítulos, listas, atributos, vínculos y jerarquías claras. Se entiende qué información pesa más y cómo se agrupa. |
| Bueno | La información está ordenada, aunque algunas secciones o atributos podrían estar mejor definidos. |
| Regular | Hay información suficiente, pero se presenta casi como texto plano o con poca jerarquía. |
| Deficiente | La información está incompleta, desordenada o no permite construir el sitio. |

## 3. Síntesis y selección de contenido

| Nivel | Descripción |
|---|---|
| Excelente | Selecciona solo la información que ayuda a comunicar la intención. Agrupa, reduce, elimina o reorganiza contenido cuando es necesario. |
| Bueno | Hay selección de contenido, aunque conserva algunos datos secundarios que no aportan mucho. |
| Regular | Acumula información sin suficiente síntesis. Hay demasiadas secciones, datos o elementos sin relación clara. |
| Deficiente | No hay selección. El sitio intenta mostrar todo sin criterio. |

## 4. Intención comunicativa

| Nivel | Descripción |
|---|---|
| Excelente | Define con precisión qué quiere comunicar, a quién y desde qué enfoque. Esa intención guía el contenido, el tono y el diseño. |
| Bueno | La intención es clara, aunque todavía podría delimitar mejor audiencia, enfoque o propósito. |
| Regular | La intención es genérica o poco útil para tomar decisiones de diseño. |
| Deficiente | No hay intención comunicativa clara. |

## 5. Mapa de sitio y organización de secciones

| Nivel | Descripción |
|---|---|
| Excelente | Presenta un mapa de sitio claro, sintético y navegable. Las secciones tienen relación con la intención y no saturan el menú ni el recorrido. |
| Bueno | El mapa de sitio funciona, aunque algunas secciones podrían agruparse o simplificarse. |
| Regular | El mapa de sitio existe, pero hay secciones redundantes, demasiadas entradas o poca relación entre partes. |
| Deficiente | No hay mapa de sitio o la organización no permite entender cómo se navegará el proyecto. |

## 6. Tono verbal y visual

| Nivel | Descripción |
|---|---|
| Excelente | Define un tono coherente con la intención. Se refleja en títulos, descriptores, CTA, lenguaje visual, referencias, colores y tipografía. |
| Bueno | El tono está definido y se percibe en varias decisiones, aunque no siempre es consistente. |
| Regular | El tono se describe con palabras generales, pero casi no se traduce al contenido o al diseño. |
| Deficiente | No hay tono definido o el tono contradice la intención del proyecto. |

## 7. Moodboard y referencias visuales

| Nivel | Descripción |
|---|---|
| Excelente | Presenta referencias concretas con screenshots, enlaces o imágenes. Explica qué recupera de ellas: color, composición, tipografía, atmósfera, ritmo o interfaz. |
| Bueno | Incluye referencias útiles, aunque falta explicar mejor cómo se traducen al proyecto. |
| Regular | Incluye pocas referencias o referencias demasiado generales. |
| Deficiente | No presenta referencias visuales o no tienen relación con el proyecto. |

## 8. Sistema visual mínimo

| Nivel | Descripción |
|---|---|
| Excelente | Define y aplica paleta de color, tipografías, escala, contraste, espaciado, enlaces, botones y estados básicos. Las decisiones son coherentes con el tono. |
| Bueno | El sistema visual está definido, aunque algunos elementos necesitan mayor consistencia o ajuste. |
| Regular | Hay colores y tipografías, pero parecen elegidos sin suficiente criterio o tienen problemas de contraste/legibilidad. |
| Deficiente | No hay sistema visual claro. Colores, tipografías y tamaños no funcionan o no fueron definidos. |

## 9. Wireframes y diseño en bloques

| Nivel | Descripción |
|---|---|
| Excelente | Presenta wireframes desktop y mobile. Se entiende la estructura de bloques, jerarquía, espacios, contenedores, navegación y adaptación. |
| Bueno | Presenta wireframes claros, aunque falta resolver algunos espacios, proporciones o comportamiento mobile. |
| Regular | Los wireframes son muy básicos o incompletos; ayudan poco a construir el sitio. |
| Deficiente | No presenta wireframes o intenta construir el sitio sin diseño previo. |

## 10. Implementación HTML/CSS y revisión

| Nivel | Descripción |
|---|---|
| Excelente | El HTML es jerárquico y semántico. El CSS usa bloques, contenedores, tamaños relativos, márgenes, padding, contraste y adaptación mobile/desktop. Las imágenes están optimizadas y no exceden 1920 x 1080 px cuando aplica. Incluye screenshots de revisión. |
| Bueno | La implementación funciona y respeta la estructura general, aunque hay detalles de jerarquía, responsive, contraste o archivos por ajustar. |
| Regular | El sitio existe, pero tiene problemas visibles de estructura, legibilidad, adaptación o consistencia visual. |
| Deficiente | El HTML/CSS está incompleto, desordenado o no corresponde al proceso documentado. |

## Reglas de revisión

- Si no hay información estructurada, no hay base para evaluar el sitio.
- Si no hay intención comunicativa, no hay forma de justificar el tono.
- Si no hay mapa de sitio, no hay claridad de navegación.
- Si no hay referencias, no hay evidencia de exploración visual.
- Si no hay wireframes, no hay diseño previo.
- Si el sitio no se prueba en mobile y desktop, la entrega está incompleta.
