# Actividad

## Sitio web en bloques

**Tagline:** Convertir información estructurada en una página web sencilla, clara y navegable.

**Descriptor:** La actividad consiste en investigar un tema, organizarlo en Markdown, definir una intención de comunicación, diseñar una estructura visual básica y construir un sitio web con HTML/CSS usando secciones en bloque.

## Objetivo

Diseñar y construir un sitio web de una sola página a partir de información investigada y estructurada. El resultado debe demostrar que la información fue seleccionada, jerarquizada, organizada en secciones y traducida a una interfaz visual coherente.

## Qué se entrega

El proyecto debe incluir:

1. `PROMPT.md`
2. `INFO.md`
3. `README.md`
4. Mapa de sitio
5. Definición de intención comunicativa
6. Definición de tono verbal y visual
7. Moodboard o referencias visuales
8. Sistema visual mínimo
9. Wireframes desktop y mobile
10. `index.html`
11. `styles.css`
12. Imágenes optimizadas, si aplica
13. Screenshots de revisión desktop y mobile

## Proceso

### 1. Investigación

Recolecta información sobre tu tema. Puedes usar inteligencia artificial, fuentes web, libros, entrevistas, archivos personales o investigación propia. Lo importante es documentar cómo llegaste a esa información.

El proceso se documenta en `PROMPT.md`.

### 2. Información estructurada

Ordena la información en `INFO.md`. No entregues una masa de texto. Usa títulos, subtítulos, listas, enlaces, atributos, categorías y jerarquías.

La pregunta central es:

> ¿Qué estructura necesita esta información para poder convertirse en sitio web?

### 3. Intención comunicativa

Define qué quieres comunicar.

Preguntas de apoyo:

- ¿Qué debe entender la persona que visite el sitio?
- ¿Qué debe sentir o notar?
- ¿Qué debe hacer después?
- ¿Qué información ayuda a comunicar eso?
- ¿Qué información sobra?

### 4. Mapa de sitio

Organiza las secciones del sitio. Aunque sea una sola página, debe existir una lógica de navegación.

Ejemplo:

```text
Inicio
  Hero
  Contexto
  Categorías principales
  Casos o ejemplos
  Cierre / CTA
```

### 5. Tono

Define tono verbal y tono visual.

El tono verbal aparece en títulos, descriptores, botones y textos. El tono visual aparece en color, tipografía, composición, ritmo y referencias.

### 6. Referencias y moodboard

Reúne referencias visuales. Pueden ser capturas de sitios, pósters, portadas, interfaces, sistemas editoriales, piezas gráficas o materiales relacionados.

Cada referencia debe explicar qué se recupera de ella:

- color;
- tipografía;
- composición;
- atmósfera;
- ritmo;
- tipo de imagen;
- tono.

### 7. Sistema visual mínimo

Define:

- color de fondo;
- color de texto;
- color de acento;
- tipografía de títulos;
- tipografía de cuerpo;
- escala tipográfica;
- estilo de botones/enlaces;
- espaciado general.

### 8. Wireframes

Diseña la estructura antes de programar.

Se pide al menos:

- wireframe desktop;
- wireframe mobile;
- estructura del hero;
- estructura de secciones principales.

Puede ser en Figma, Illustrator, Photoshop, dibujo a mano o captura de boceto. Lo importante es que exista una decisión de layout antes del HTML.

### 9. HTML/CSS

Construye el sitio con HTML y CSS.

En esta etapa se trabaja con bloques verticales:

- `header`;
- `main`;
- `section`;
- `footer`;
- `.container`;
- títulos;
- párrafos;
- listas;
- enlaces;
- imágenes.

No se requiere `flex`, `grid`, tablas ni JavaScript.

### 10. Revisión

Prueba el sitio en desktop y mobile.

Entrega capturas donde se vea:

- hero en desktop;
- hero en mobile;
- una sección interior en desktop;
- una sección interior en mobile.

## Reglas técnicas

- Las imágenes no deben exceder 1920 x 1080 px cuando se usen como material visual general.
- Las imágenes deben estar en formato adecuado: `.jpg`, `.png`, `.webp` o `.svg` según corresponda.
- La tipografía display no debe usarse para cuerpos largos de texto si afecta la lectura.
- Debe existir contraste suficiente entre texto y fondo.
- El sitio debe poder leerse en mobile.

## Resultado esperado

Un sitio sencillo, bien organizado y visualmente coherente.

El sitio no necesita ser complejo. Necesita demostrar que cada decisión viene de un proceso: información, intención, estructura, tono, sistema visual, wireframe e implementación.
